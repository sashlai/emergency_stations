# Травмпункты Москвы

Учебное веб-приложение для поиска травмпунктов на карте и сбора оценок качества обслуживания.

**Стек:** JavaScript, PHP 8.2+, MySQL 8.0.16+ / MariaDB 10.4+, Leaflet 1.9.3, OpenStreetMap. Без сборки и фреймворков.

## Возможности

- Карта организаций, поиск по названию с подсказками и выбор из списка.
- Управление подсказками с клавиатуры: ↑ / ↓, Enter и Escape.
- Карточка организации с категорией, руководителем, режимом работы и возрастной категорией.
- Оценка визита по шести критериям и статистика по каждой организации.
- Общий рейтинг с количеством отзывов; организации без отзывов выводятся после оценённых.
- Сообщения о загрузке, ошибках и пустых результатах, повторная загрузка при сбое.
- Адаптивная форма и горизонтальная прокрутка таблицы на узких экранах.

## Локальный запуск

Нужны PHP 8.2+ с расширением `mysqli` и поддержкой `mysqlnd`, MySQL или MariaDB. В Windows можно использовать PHP и MariaDB из XAMPP. Команды выполняются из каталога проекта; если программы не добавлены в PATH, укажите полный путь к ним.

1. Скачайте репозиторий:

   ```sh
   git clone https://github.com/sashlai/emergency_stations.git
   cd emergency_stations
   ```

2. Запустите сервер БД. В phpMyAdmin либо в консоли MySQL создайте **новую пустую базу**:

   ```sql
   CREATE DATABASE emergency_stations CHARACTER SET utf8mb4;
   ```

   Импортируйте в неё `emergency_stations.sql`. В консоли MySQL:

   ```sql
   USE emergency_stations;
   SOURCE /absolute/path/to/emergency_stations.sql;
   ```

   В Windows в `SOURCE` используйте прямые слеши, например `C:/projects/emergency_stations/emergency_stations.sql`. Дамп содержит каталог и четыре тестовых отзыва; повторно в заполненную базу его импортировать не нужно.

3. Создайте отдельного пользователя приложения (задайте собственный пароль):

   ```sql
   CREATE USER 'emergency_app'@'127.0.0.1' IDENTIFIED BY 'replace-with-your-password';
   GRANT SELECT, INSERT ON emergency_stations.* TO 'emergency_app'@'127.0.0.1';
   ```

4. Скопируйте `config.example.php` в `config.local.php` и заполните настройки подключения. Этот файл исключён из Git. Учётная запись `root` приложению не нужна.

5. Запустите веб-сервер:

   ```sh
   php -d display_errors=0 -d log_errors=1 -S 127.0.0.1:8000
   ```

   Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). HTML-файл нужно открывать через сервер, а не двойным щелчком. Ошибки PHP записываются в журнал, чтобы не нарушать формат JSON-ответов. Встроенный сервер предназначен для локальной разработки.

Для XAMPP также можно положить каталог в `htdocs`, заполнить конфиг и открыть `http://localhost/emergency_stations/`. Относительные адреса API поддерживают и корень сайта, и подпапку. В настройках PHP должны быть `display_errors=Off` и `log_errors=On`.

Для карты и её оформления нужен интернет: Leaflet загружается с unpkg, тайлы — с OpenStreetMap. Если библиотека карты недоступна, поиск и выбор из списка остаются доступны.

## Как устроен проект

| Файл | Назначение |
|---|---|
| `index.html`, `script.js` | Карта, поиск, форма оценки и статистика |
| `centers.html`, `centers.js` | Таблица рейтингов |
| `styles.css` | Общие стили и адаптивная вёрстка |
| `api.js` | Общая обработка JSON-ответов и сообщений |
| `api.php` | Подключение к БД, HTTP-методы, проверка ID и обработка ошибок |
| `db_connection.php` | GET: каталог организаций (историческое имя endpoint) |
| `get_statistics.php?id=1` | GET: статистика одной организации |
| `all_centers.php` | GET: общий рейтинг |
| `save_rating.php` | POST: сохранение оценки |
| `emergency_stations.sql` | Схема, исходный каталог и демонстрационные отзывы |
| `tests/` | Проверки API и логики интерфейса |

POST `/save_rating.php` принимает JSON с `id`, `waiting_time`, `professionalism`, `politeness`, `clarity`, `cleanliness`, `visit_time`. ID должен быть положительным целым числом и существовать в каталоге. Каждая оценка — целое число от 1 до 5. Числовые строки также поддерживаются.

Успешное сохранение возвращает `201` и `{"success":true}`. Ошибки: `400` — некорректный JSON, `404` — организация не найдена, `405` — неподдерживаемый метод, `413` — тело запроса больше 16 КиБ, `415` — неверный Content-Type, `422` — неверные поля, `500` — внутренняя ошибка. Клиент не получает SQL и подробности подключения.

Общая оценка — среднее арифметическое шести оценок каждого отзыва, усреднённое по всем отзывам организации. Показатели скорости приёма и длительности визита — **баллы, а не минуты**. При отсутствии отзывов количество равно `0`, средние значения — `null`.

## Проверки

Используйте локальную **тестовую базу** и сервер, запущенный из той же копии проекта, чей `config.local.php` используют проверки. Нужны Python 3, PHP CLI и Node.js для проверки логики интерфейса.

Для интеграционных проверок временно разрешите тестовому пользователю удалять созданную тестовую организацию:

```sql
GRANT DELETE ON emergency_stations.* TO 'emergency_app'@'127.0.0.1';
```

```sh
python tests/smoke.py http://127.0.0.1:8000
node tests/interaction.cjs
```

Если `php` отсутствует в PATH, задайте переменную окружения `PHP_BIN` с путём к PHP. Проверка API создаёт отдельную организацию, отправляет тестовые отзывы и удаляет её вместе с отзывами в блоке `finally`. Существующие организации не изменяются. После проверки право DELETE можно отозвать:

```sql
REVOKE DELETE ON emergency_stations.* FROM 'emergency_app'@'127.0.0.1';
```

Проверяются сохранение, границы шкалы, расчёт средних, пустая статистика, неизвестные ID, неверный JSON и типы данных, HTTP-методы и согласованность рейтингов. Проверки JavaScript выполняются с имитацией DOM и сетевых ответов; они не заменяют проверку в настоящем браузере.

## Данные и ограничения

Источник справочника — [открытые данные Москвы: «Травматологические пункты»](https://data.mos.ru/opendata/1260?pageSize=10&pageIndex=0&isDynamic=false&version=2&release=158). В репозитории хранится статический снимок из исходного дампа января 2025 года; автоматического обновления нет. Четыре исходных отзыва — демонстрационные, они не отражают реальное качество услуг. Для актуальной информации обращайтесь к организации.

Отзывы анонимны. Блокировка кнопки предотвращает повторный клик во время отправки, но не является защитой от накрутки. Перед публичным запуском нужны ограничение частоты запросов, решение о модерации, HTTPS и проверка настроек хостинга. Демо пока не опубликовано.

Перед добавлением проекта в резюме: проверить карту и форму в браузере на компьютере и телефоне, добавить реальные скриншоты в README и разместить демонстрацию на хостинге с PHP и MySQL/MariaDB. GitHub Pages не выполняет PHP.
